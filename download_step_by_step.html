Publishing an Installer — Step by Step

Move a finished Windows installer from a private product build to a public GitHub release, then use a branded website redirect so customers click your product domain instead of a GitHub username.

1. Download the installer from the private product build

  1. Open the product's private GitHub build repository (for example, OptionsPlotter-build).
  2. Click Releases and open the latest successful build release.
  3. Under Assets, download the compiled .exe to your computer.
  4. Keep the exact installer filename; you'll use it in the public release.

2. Create a release in TraderRepository-Downloads

  1. Open TraderRepository-Downloads → Releases.
  2. Select Draft a new release.
  3. Choose Create new tag, for example optionsplotter-premium-v1.0.0, targeting main.
  4. Fill in the Release title and Description.
  5. Under Attach binaries by dropping them here or selecting them, upload the .exe downloaded in Step 1.
  6. Wait for the upload to finish, then click Publish release.

Important: The public installer belongs in TraderRepository-Downloads, not in the private product build repository. Basic and Premium can use separate release tags.

3. Copy the full public installer URL

  1. Open the newly published release in TraderRepository-Downloads.
  2. Find the installer under Assets.
  3. Right-click the .exe asset and choose Copy link address.
  4. Verify the link includes TraderRepository-Downloads/releases/download/, followed by your tag and exact filename. Do not copy the old OptionsPlotter-build URL.

Example — Options Plotter Basic v1.0.0:

https://github.com/MarkB2026/TraderRepository-Downloads/releases/download/optionsplotter-basic-v1.0.0/OptionsPlotter_Basic_Beta_v1.0.0.exe

4. Create the branded download redirect

  1. Open the public GitHub repository for the product website.
  2. Create download.html in the repository root. If Basic already uses that name, use download-premium.html for Premium.
  3. Paste the template below and replace PASTE_PUBLIC_EXE_URL_HERE in both places with the full URL copied in Step 3.
  4. Commit the file. GitHub Pages will publish it with the website.
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="robots" content="noindex,nofollow">
  <title>Starting your download…</title>
  <meta http-equiv="refresh"
        content="0;url=PASTE_PUBLIC_EXE_URL_HERE">
</head>
<body>
  <p>Your download is starting…</p>
  <p><a href="PASTE_PUBLIC_EXE_URL_HERE">
    Click here if it doesn't start.
  </a></p>
</body>
</html>

Branded example: https://optionsplotter.com/download-premium.html

5. Update the website download buttons

  1. Open the website's root index.html.
  2. Find each button for the edition you are publishing.
  3. Change its link to the relative redirect path, for example href="download.html" for Basic or href="download-premium.html" for Premium.
  4. If the button is controlled by JavaScript rather than a normal link, update that click handler to navigate to the redirect.
  5. Commit index.html. Preserve unrelated styling, videos, payment checkout, and license logic.

Paid editions: Do not replace a purchase or Bitcoin checkout button with a public download button unless that's the intended access model. Link the installer from the appropriate post-purchase flow instead.

6. Test the customer download

  1. Open the product website in a private/incognito window.
  2. Click the relevant download link or visit the branded download.html URL directly.
  3. Confirm the correct .exe downloads without a GitHub login.
  4. Check the installer filename and edition. Confirm the website's payment flow still works independently.

Future versions — what changes?

Build the new installer, publish a new public release and copy its new asset URL. Then update the existing redirect file with that URL. The website button stays the same as long as the redirect filename stays the same.

What the redirect masks: Customers see your branded link when hovering over the website button. The final file is still hosted by GitHub, so the GitHub address can appear in download details or network inspection.
